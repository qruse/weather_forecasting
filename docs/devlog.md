> 블로그용 기록이라 삽질도 숨기지 않고 적는다. 새 글은 맨 아래에 이어서 쓴다.

## Day 1 (2026-10-08) — 링에 올라가기 전에 룰부터

### 1. 룰 정하기
"기상청을 이긴다"는 말은 멋있지만, 룰이 없으면 이겼는지도 알 수 없다. 그래서 먼저 판을 깔았다.

| 항목 | 정한 것 |
|---|---|
| 지점 | 서울(ASOS 108), 대구(ASOS 143) |
| 리드타임 | 단기 0~48시간 |
| 강수 | **1mm 이상이면 비**, 지표는 **F1** |
| 나머지 | 기온·습도·풍속 **MAE** |
| 장비 | Colab **L4** (시간당 약 700원, 200CU면 약 40시간) |
| 방식 | 후처리 보정 없이 **정면 대결** |

강수를 정확도로 안 하고 F1으로 한 이유는 간단하다. 비 안 오는 날이 훨씬 많아서, "항상 안 온다"만 찍어도 정확도는 높게 나온다. 그건 예측이 아니라 배짱이다.
후처리 보정으로 기상청 예보를 살짝 고치는 길도 있었지만, 그건 이겨도 "기상청 덕분에 이긴" 거라 의미가 없다고 봤다.

### 2. 저장소 개설
`qruse/weather_forecasting`을 만들고 공개로 돌렸다. 폴더 이름은 `wearher_forecasting`으로 오타가 났는데, 아직 안 고쳤다. 이것도 기록의 일부다.

### 3. 데이터 파이프라인
- **ERA5** (입력 기상장): 서울·대구 2018~2025년 시간자료, 각 70,128행을 받았다. 처음엔 한 번에 8년치를 요청했다가 `429 Too Many Requests`로 쫓겨났다. 연 단위로 쪼개고 재시도를 넣어서 해결했다.
- **기압면 변수**(850hPa 등)는 받아 보니 전부 NaN이었다. 에러도 없이 빈 칸으로 오는 게 더 얄밉다. 결국 지상 변수 11개만 쓰기로 했다.
- **ASOS** (정답)와 **동네예보** (상대): 스크립트는 만들어 뒀는데 공공데이터포털 인증키가 없어서 아직 못 돌렸다.

여기서 제일 중요한 사실 하나. **기상청 동네예보 API는 며칠 치만 준다.** 지금 모으기 시작하지 않으면 상대 선수의 과거 기록이 영영 안 남는다. 그래서 GitHub Actions로 3시간마다 예보를 긁어 쌓는 워크플로를 짰다.

### 4. 삽질 모음
- **GitHub 토큰에 `workflow` 권한이 없어서** 워크플로 push가 거부당했다. 일단 `ci/` 폴더에 두고, 권한을 올린 뒤 옮길 예정이다.
- **한글이 전부 깨졌다.** PowerShell로 문자열 치환을 하다가 인코딩을 지정 안 한 탓이다. README와 주석이 `?띿냽` 같은 글자로 바뀐 채 푸시됐다. 곧바로 이전 커밋에서 복구해서 UTF-8로 다시 적용했다. 깨진 커밋은 히스토리에 남아 있다.
- **임계값을 0.1mm와 1mm 병행으로 했다가** 1mm 하나로 확정했다. 지표는 단순할수록 싸울 때 헷갈리지 않는다.

### 5. SOTA 조사: 누구 어깨 위에 올라탈까
2025년 이후 모델들을 훑었다.

- **Aurora (Microsoft):** 가중치 공개, 1.5 버전은 변수 26개에 시간 단위 예보. 단기 파인튜닝 뒤 LoRA로 롤아웃 파인튜닝하는 공식 레시피가 있다. 우리 쪽 1순위.
- **FourCastNet 3 (NVIDIA):** 성능은 좋지만 GPU 메모리 60GB가 필요하다. L4는 24GB라서 탈락.
- **AIFS (ECMWF):** 2025년 운영 시작, 6시간 간격 예보를 무료로 공개한다. 입력 후보.

그리고 찬물 한 바가지. 서발칸 100개 지점 연구에서는 **강수 예측에서 단순 기후평균이 딥러닝 5종을 전부 이겼다.** 지점 단위 강수는 그만큼 어렵다. 사전학습 기상장 모델 위에 얹는 이유가 여기 있다.

상대도 만만치 않다. 기상청은 2026년 4월부터 한국형 수치모델(KIM)만 단독 운영하고 있고, 한국형 AI 파운데이션 모델도 개발 중이다.

### 6. 작전
1. 백본: Aurora small을 서울·대구 주변 격자로 잘라 입력. 처음엔 고정하고, 성능이 나오면 LoRA.
2. 우리가 짜는 부분: 격자 표현에서 두 도시 좌표 주변을 읽는 지점 디코더, 강수 분류 헤드(1mm 이상), 기온·습도·풍속 회귀 헤드.
3. 데이터 분할: 2018~2023 학습, 2024 검증, 2025 테스트.
4. 데이터 보강: 지점별 CSV로는 Aurora 입력을 못 만든다. 격자 ERA5(WeatherBench2)로 갈아탄다.

## Day 1 (밤) — GPU는 구글 땅에 있다

GPU는 Colab에서 돌려야 하는데, 내 작업 환경은 로컬 PC다. 코드는 로컬과 GitHub, 계산은 구글 서버. 이 둘을 어떻게 이을지가 오늘의 숙제였다.

답은 단순하게 갔다. **GitHub이 다리다.**
- 코드는 로컬에서 짜서 push하고, Colab은 clone/pull로 받는다. 저장소가 공개라 인증이 필요 없다.
- 데이터와 체크포인트는 **Google Drive**에 둔다. Colab 세션은 언제 끊길지 모르는데, 한 번 끊기면 디스크가 통째로 날아간다. 200CU 태워서 학습한 결과가 사라지는 건 상상도 하기 싫다.
- 인증키는 Colab Secrets에 넣는다. 노트북에 키를 박으면 공개 저장소에 그대로 올라가니까.

`notebooks/00_colab_setup.ipynb` 하나로 GPU 확인, Drive 마운트, clone, 의존성 설치, 데이터 준비까지 끝나게 만들었다. README에 "Open in Colab" 버튼도 달았다.

작은 함정 하나. 처음엔 `data/raw` 폴더 전체를 Drive로 연결(symlink)하려 했는데, 그 안에 git이 추적하는 예보 수집 파일이 들어갈 예정이라 pull할 때 충돌이 날 것 같았다. 그래서 gitignore된 `asos/`, `era5/`, `checkpoints/`만 Drive로 연결하게 바꿨다.

아직 L4가 실제로 잡히는지, 노트북이 처음부터 끝까지 도는지는 확인 전이다. 그건 사람이 직접 한 번 돌려 봐야 안다.
